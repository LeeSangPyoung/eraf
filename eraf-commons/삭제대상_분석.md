## ❌ 삭제 대상 후보 (Excel에 없음)

### 1. 즉시 삭제 검토 필요 (2개)

#### ⚠️ eraf-observability
- **현재 기능**: MetricsUtil, TracingUtil, OpenTelemetry 통합
- **Excel 대응**: No.69-72 "메트릭/추적"이 모두 **eraf-actuator**에 포함됨
- **문제**: eraf-actuator와 기능 중복 가능성
- **권장 조치**:
  ```
  1. eraf-actuator와 기능 비교
  2. 중복이면 eraf-actuator로 통합
  3. 고유 기능 있으면 유지 (Excel 업데이트)
  ```

#### ⚠️ eraf-outbox
- **현재 기능**: Outbox Pattern 구현
- **Excel 대응**: No.56 "Outbox 패턴"이 **eraf-messaging-kafka** 하위 항목
- **문제**: 범용 vs Kafka 전용 불명확
- **권장 조치**:
  ```
  1. 범용 패턴이면 → 유지 (Excel 업데이트)
  2. Kafka 전용이면 → eraf-messaging-kafka로 통합 후 삭제
  ```

- **결론**: **유지 필수**

## 📋 최종 권장 조치사항

### 즉시 조치 (필수)

#### 1. eraf-observability 검토
```bash
# eraf-actuator와 기능 비교
cd /d/workspace_eraf/eraf2/eraf-commons

# observability 기능 확인
grep -r "class.*Util" eraf-observability/src/main/java/

# actuator 기능 확인
grep -r "class.*Util" eraf-actuator/src/main/java/

# 중복 여부 판단 후:
# - 중복이면: eraf-observability 삭제, eraf-actuator로 통합
# - 다르면: 유지 (Excel에 eraf-observability 추가)
```

#### 2. eraf-outbox 검토
```bash
# outbox 사용처 확인
grep -r "OutboxMessage\|OutboxService" eraf-commons --include="*.java"

# Kafka 의존성 확인
cat eraf-outbox/pom.xml | grep -i kafka

# 판단:
# - Kafka 전용이면: eraf-messaging-kafka로 이동
# - 범용이면: 유지 (Excel에 독립 항목으로 추가)
```

## 💡 핵심 인사이트

### Excel vs 구현의 차이점
- **Excel**: "큰 기능 단위" 모듈 (33개)
- **구현**: "세분화된" 모듈 (45개)

### 왜 구현이 더 많은가?
1. **모듈 세분화**: eraf-core → eraf-core-* 9개
2. **인프라 모듈**: eraf-bom, eraf-test
3. **패턴 모듈**: eraf-web, eraf-observability, eraf-outbox

### 권장 사항
- **Excel을 "요구사항"**, **pom.xml을 "구현 구조"**로 이해
- 현재 모듈 구조가 더 나은 설계 (단일 책임 원칙)
- Excel을 실제 모듈 구조와 동기화 권장
